# MONO DECK

A73T 15키 + 3노브 매크로 키보드를 위한 Windows 컨트롤 스튜디오입니다. USB `1189:8840` 장치를 직접 읽고, Windows Raw Input으로 일반 키보드와 구분합니다. v2.6.4는 기기 그룹 1·2·3, 온보드 0, 여러 PC 페이지, RGB 조명, 녹화·조건·반복을 포함한 매크로 스튜디오를 제공합니다.

Windows control studio for A73T 15-key / 3-knob macro keyboards: PC pages, onboard mappings, mixed keyboard/mouse macros, RGB controls, portable presets, and OBS audio/scene control.

## 소스에서 시작하기

다른 PC나 새 Codex에서 이어서 개발한다면 **[개발 인수인계서](docs/HANDOFF.md)**와 **[Codex 작업 규칙](AGENTS.md)**을 먼저 읽으세요. 실제 확인된 동작과 남은 제한은 **[검증 기록](docs/verification.md)**에 있습니다.

Windows x64, Node.js 22.12 이상과 Windows 기본 .NET Framework 4.x C# 컴파일러가 필요합니다.

```powershell
git clone https://github.com/anthonykim3197/mono-deck.git
cd mono-deck
npm ci
npm run build
npm test
npm start
```

배포용 폴더는 `npm run package`로 만듭니다. 생성된 `release/win-unpacked/` 폴더 전체를 함께 사용하세요. 이 저장소에는 개인 설정, 장치별 원본 백업, 제조사 실행 파일, 생성된 배포 바이너리를 포함하지 않습니다.

## 실행

`release/win-unpacked/MONO DECK.exe`를 실행하세요. 배포 폴더 전체가 필요합니다. 닫기 버튼은 트레이로 최소화하며, 트레이 메뉴의 **종료**로 완전히 종료합니다.

1. 기기를 USB로 연결합니다.
2. 앱에서 편집할 **1·2·3번 레이어**를 선택합니다. 연결되지 않은 레이어는 **입력 연결**로 매핑을 백업하고 앱 전용 신호를 설정합니다.
3. 키 또는 노브의 회전/누르기를 선택하고 동작을 지정한 뒤 **PC에 액션 저장**을 누릅니다.
4. 기기의 물리 Layer 버튼으로 같은 그룹을 선택하고 오른쪽 위 전환 노브를 한 번 돌립니다. 앱에 마지막 확인된 기기 그룹과 확인 시간이 표시됩니다. 앱의 그룹 선택은 편집 대상을 바꾸며 기기의 물리 스위치를 대신하지 않습니다.
5. 앱을 최소화하고 사용할 프로그램에서 매크로를 누릅니다. **입력 모니터**에서 최근 입력의 레이어와 키를 확인할 수 있습니다.

MONO DECK 편집창이 앞에 있을 때는 기기 입력만 표시합니다. 매크로 스튜디오의 **시험 실행**은 2초 후 시작하므로 대상 앱으로 전환하세요. 편집창에 머무르거나 실행 중 돌아오면 취소됩니다. 장치 진단의 텍스트 출력 시험은 지정된 앱 입력란에서 시험하는 예외입니다.

개발용 A73T 한 대에서 3개 레이어의 전용 신호 72개를 기록하고 읽기 검증했습니다. 각 레이어의 대표 키, 노브 입력과 청록색 반응 조명도 실물 확인했습니다. 판매 버전이나 펌웨어가 다른 모든 장치의 호환성을 보장하지는 않습니다. 검증 범위는 [검증 기록](docs/verification.md)에 정리했습니다.

## 지원하는 동작

- 단축키: Ctrl / Shift / Alt / Win과 F키·방향키·기호 조합, 직접 기록
- 텍스트 입력: 한글과 유니코드 지원, 클립보드 내용을 바꾸지 않음
- 웹사이트 열기, `.exe` 프로그램 실행 및 인수
- 볼륨, 음소거, 재생/정지, 이전/다음 곡
- 키 누르기/떼기, 마우스 이동·클릭·누르기·떼기·세로 스크롤
- 단계별 지연과 무작위 지연, 실행 속도, 중첩 반복, 같은 키로 시작/중지하는 반복
- 창의 프로세스/제목 또는 픽셀 색상에 따른 조건 분기와 조건 대기
- 키보드·마우스 녹화, 순서 변경·복제·비활성화·주석, 입력 없는 실행 계획 검증
- 화면별 물리 픽셀 좌표, 가상 화면의 음수 좌표, 상대 이동, 포인터/색상 가져오기
- 하드웨어 레이어마다 별도 액션, 레이어 간 액션 복사, 전역 실행 단축키
- 프로필 전환, 전경 프로그램 이름에 따른 자동 프로필 전환
- 키 이름·아이콘·색상, 노브 위치/회전 방향 보정
- 프로필 내보내기/가져오기, 트레이 일시 정지, Windows 로그인 시 실행
- 선택한 PC 페이지의 프리셋 파일 가져오기·내보내기, 기존 설정 보존과 추천 프리셋 중복 방지
- OBS WebSocket 5를 통한 장면 후보·확정, 소스 볼륨·음소거, 녹화·리플레이·스튜디오 모드 제어
- 실제 장치 조회, 전체 매핑 백업, 선택 레이어 또는 전체 레이어 연결/복원
- 레이어별 조명 끄기·상시 조명·패턴 2·패턴 3·누를 때 반응, 하드웨어 색상 프리셋

Everyday, Creative 기본 프로필이 포함됩니다. Creative의 자동 전환 대상은 Photoshop이며 설치되어 있지 않아도 기본 프로필은 사용할 수 있습니다. 다른 프로그램에는 원하는 단축키를 지정하세요. 예를 들어 OBS에서 설정한 전역 단축키를 동작으로 지정할 수 있습니다.

기존 프로필의 액션은 3번 레이어로 이전됩니다. 1·2번 레이어에는 새 액션을 지정하거나 다른 레이어의 구성을 복사하세요. 액션 복사와 PC 페이지끼리의 전환은 앱 설정만 바꿉니다. 0번을 포함한 모든 페이지 선택은 PC 안에서 즉시 바뀝니다. 기기 기록은 별도 버튼으로 실행합니다.

## 매크로 스튜디오

키를 선택한 뒤 **매크로 스튜디오**를 열어 동작을 순서대로 추가합니다. 조건 블록은 참/거짓 가지를, 반복 블록은 안쪽 동작과 횟수를 편집합니다. 키나 마우스 버튼을 누른 상태로 유지할 수 있으며 완료·오류·중지 시 프로그램이 보유한 입력을 해제합니다.

**동작 녹화**는 안내를 확인하고 시작할 때만 켜집니다. 2초 안에 대상 앱으로 이동하세요. 기본적으로 키보드와 마우스 버튼·스크롤을 기록하며, 이동 경로 기록은 선택 사항입니다. 클릭 위치도 저장됩니다. 녹화 중에는 다른 앱의 입력이 기록되므로 비밀번호 등 저장할 필요가 없는 내용은 입력하지 마세요. 녹화 결과를 단계로 추가한 뒤 저장합니다.

**실행 없이 검증**은 입력 전송, 앱 실행, 화면/창 조회 없이 구성과 실행 계획을 확인합니다. 화면 조건이 실제로 참인지 확인하는 시험은 아닙니다. **시험 실행** 후에는 대상 앱으로 전환하세요. **즉시 중지** 또는 **Ctrl+Alt+Esc**로 녹화/실행을 중지할 수 있습니다. 전역 단축키 등록 실패가 표시되면 화면의 중지 버튼을 사용하세요.

매크로 하나는 루트·분기를 포함해 최대 500개 동작 노드, 중첩 5단계입니다. 개별 지연/조건 대기는 최대 1시간, 반복은 최대 10,000회, 속도는 0.1~10배입니다. 같은 키로 시작/중지하는 반복은 매크로 전체에만 적용합니다. 반복 횟수와 속도에 따라 총 실행 시간은 개별 지연 제한보다 길어질 수 있습니다.

모니터 좌표는 물리 픽셀 기준입니다. 선택한 모니터가 사라지거나 내부 좌표가 범위를 벗어나면 해당 동작은 실패합니다. 가상 화면의 왼쪽·위쪽 모니터는 음수 좌표를 사용합니다. 실제 다중 모니터 환경은 아직 확인하지 않았으며 음수 좌표 변환은 자동 테스트로 검증했습니다.

## 하드웨어 조명

**하드웨어 조명**에서 레이어·효과·색을 골라 적용합니다. 빨강·주황·노랑·초록·청록·파랑·보라 프리셋을 지원하며 흰색은 상시 조명용입니다. **누를 때 반응 + 청록**은 연결된 기기에서 실제 확인했습니다. 패턴 2·3의 정확한 모양과 전원 재연결 후 설정 유지 여부는 아직 확인하지 않았습니다.

화면은 적용할 설정과 마지막 요청을 보여주며 기기에서 현재 RGB 상태를 읽지는 않습니다. 개별 키의 임의 RGB 색상, 사용자 제작 프레임 애니메이션, 밝기/효과 속도 제어는 지원하지 않습니다. 누를 때 반응하는 효과는 기기 펌웨어가 처리합니다.

## 데이터와 하드웨어

프로필은 `%APPDATA%/mono-deck/profiles.json`, 그룹별 온보드 0 보관본은 같은 폴더의 `onboard-banks/`, 새 매핑 백업은 `backups/`에 저장됩니다. 온보드 보관본은 PC 프로필 내보내기에 포함되지 않습니다. **설정 → 데이터 폴더**로 열 수 있습니다. 계정·클라우드 저장은 사용하지 않습니다. 웹사이트 실행은 지정한 브라우저 주소를 열고, OBS 기능은 사용 시 이 PC의 `127.0.0.1` WebSocket 서버에 연결합니다. OBS 인증 정보는 로컬 OBS 설정에서 읽으며 프리셋에 내보내지 않습니다.

액션 편집 내용은 **PC에 액션 저장** 또는 스튜디오 저장 버튼을 눌러야 PC 프로필에 저장됩니다. 입력할 때마다 자동 저장하거나 기기에 업로드하지 않습니다. 프로필/레이어 선택, 설정 토글, 노브 보정은 적용 시 PC에 저장됩니다.

**기기 저장 / 가져오기**에서 지원되는 단축키·미디어·최대 18개 키보드 연속 입력을 검토하고 저장합니다. 선택한 항목을 0번 PC 보관본에만 저장하거나, 별도 버튼으로 기기에도 기록할 수 있습니다. 제외한 항목은 기존 0번 설정을 유지하며 전환 노브는 공통으로 남습니다. 다른 PC에서 직접 입력을 사용하려면 연결을 끊기 전에 0번 편집기의 **기기에 쓰기 검토 → 그룹 N 기기에 기록**을 실행하세요. Ctrl+Alt+0은 PC 실행 페이지를 선택하는 단축키입니다. 앱을 종료하거나 USB를 빼도 마지막 적용 상태가 남으며 자동으로 0번을 다시 기록하지 않습니다. 직접 입력에는 MONO DECK이 필요하지 않지만 페이지 전환 노브에는 앱이 필요합니다. 대상 OS·앱·키보드 배열에 따라 단축키의 결과는 달라집니다. 복잡한 녹화·조건·좌표·앱 실행·지연은 PC 매크로로 남습니다. 다른 PC에서 이를 사용하려면 MONO DECK과 내보낸 프로필, 필요한 대상 앱을 함께 준비해야 합니다.

**기기에서 읽기**는 실제 저장된 72개 매핑을 표시합니다. **보관된 온보드 0 읽기**는 PC 모드 중에도 별도로 보관한 0번 내용을 읽습니다. 해석 가능한 기본 입력은 편집할 수 있고, 알 수 없는 형식과 추가 데이터는 원본을 보존해 표시합니다. 이름·아이콘·PC 프로필·기존 지연·현재 RGB는 이 읽기로 복구되지 않습니다. 기기 직접 입력 상태에서는 PC 액션을 중복 실행하지 않습니다. PC 연결 준비 후에는 0번과 일반 PC 페이지를 즉시 오갈 수 있습니다. [저장 범위와 프로토콜 설명](docs/onboard-storage.md)을 참고하세요.

설정용 HID는 인터페이스 0, Usage Page `FF00`, Usage `0001`, Report ID `03`, 총 65바이트입니다. 3번 레이어에는 F13–F24 및 Shift+F13–F24를, 1번에는 Ctrl을 더한 조합을, 2번에는 Ctrl+Alt를 더한 조합을 배치하여 72개 신호를 구분합니다. 기기의 펌웨어를 플래시하지 않습니다.

**매핑 백업은 펌웨어 전체 이미지가 아닙니다.** 장치 읽기 명령은 키/노브의 매핑만 반환하며, 기존 매크로 타이밍과 RGB 설정 전체를 백업하지 못합니다. 매핑 연결/복원 전에 72개를 백업하고, 선택한 레이어만 기록한 뒤 전부 다시 읽어 변경 내용과 나머지 레이어의 보존을 검증합니다. 조명 적용도 매핑을 백업하고 변경되지 않았는지 검사하지만 이전 RGB 설정을 복원할 수는 없습니다.

노브 번호와 회전 방향은 판매 버전에 따라 달라질 수 있습니다. **설정 → 노브 배치·회전 방향**에서 화면 위치를 바꾸고 방향을 뒤집으세요. 현재 활성 하드웨어 레이어를 직접 조회하거나 전환하는 명령은 확인되지 않았습니다. **최근 입력 레이어**는 마지막으로 수신한 전용 신호에서 확인한 값입니다.

Raw Input은 입력을 관찰하며 원래 F13–F24 신호를 차단하지 않습니다. 대상 앱이 그 키를 별도로 사용하면 충돌할 수 있습니다. 관리자 권한으로 실행된 앱은 Windows 권한 경계 때문에 일반 권한 앱이 보내는 입력을 거부할 수 있습니다.

## 개발

Node.js 22.12 이상과 Windows의 .NET Framework 4.x C# 컴파일러가 필요합니다. 별도 Python, .NET SDK, 드라이버 설치는 필요하지 않습니다.

```powershell
npm ci
npm run build
npm start
npm test
npm run package
```

Electron 45가 작업 폴더의 AppContainer ACL 때문에 시작하지 못한다면 `scripts/start.ps1`을 사용하세요. 이 스크립트는 생성된 Electron 바이너리 폴더에만 샌드박스 실행에 필요한 읽기/실행 권한을 추가합니다. 브라우저 샌드박스는 계속 활성화됩니다.

`npm run probe`는 장치 식별과 3개 레이어를 읽기만 하고 `.local/evidence/device-readback.json`에 보관합니다. `node scripts/observe-input.cjs`는 이 장치만 3분 동안 관찰합니다. 일반 키보드 입력은 출력하지 않습니다.

## 구조와 검증

- `src/main/protocol.cjs`: HID 프레이밍, 엄격한 장치 확인, 읽기/백업/쓰기/검증/복원
- `src/main/onboard.cjs`: 기기 직접 저장 호환성 미리보기, 기본 입력 인코딩/디코딩
- `src/main/mode-manager.cjs`: 그룹별 온보드 보관본, 0/PC 모드 전환, 기록 진행·복구 검증
- `native/Bridge.cs`: 장치별 Raw Input, SendInput, 녹화, 화면/픽셀/전경 조회
- `src/main/macro-engine.cjs`: 순차 실행, 취소, 반복, 조건, 좌표 변환, 실행 계획
- `src/main/main.cjs`: 프로필, IPC, 트레이, 녹화 연결, 자동 전환
- `src/renderer/`: React 제어 화면
- `tests/`: 프로토콜/설정/매크로 엔진/네이티브 회귀 테스트
- `docs/protocol-research.md`: 공개 소스와 관찰 사실, 남은 불확실성
- `docs/vendor-analysis.md`: 제공된 제조사 실행 파일 분석
- `docs/rgb-layer-research.md`: RGB 패킷과 다중 레이어 근거
- `docs/verification.md`: 실제 확인한 동작과 아직 확인하지 않은 범위

서명되지 않은 개인용 빌드입니다. 판매사와 무관한 독립 구현이며, 제조사 실행 파일은 배포본에 포함하지 않습니다.

## PC 페이지 삭제

페이지를 선택하고 키보드 그림 위의 **페이지 삭제**를 누릅니다. 다른 키에서 이 페이지로 이동하도록 설정돼 있으면 해당 위치를 표시하고 **연결 해제하고 삭제**를 제공합니다. 연결된 이동 동작만 비우고, 나머지 키와 매크로 단계는 유지합니다. 삭제 전 전체 설정은 데이터 폴더의 `page-backups/`에 자동 백업합니다. [페이지 관리 안내](docs/pc-pages.md)를 참고하세요.


## v2.5 · 기기 호환 0번 프리셋과 PC 페이지

기존 프로필은 화면에서 **PC 페이지**로 표시됩니다. 기기 그룹 1·2·3마다 온보드 0을 따로 보관하고, 각 PC 페이지에도 그룹별 액션 구성이 있습니다.

- 오른쪽 위 작은 노브: 온보드 0부터 모든 PC 페이지까지 왼쪽/오른쪽 회전으로 후보 선택, 누르기로 확정. 10번 이후도 선택할 수 있으며 8초 동안 조작하지 않으면 후보를 취소합니다. 이 노브는 모든 그룹·페이지에서 공통으로 고정됩니다.
- Ctrl+Alt+0: 그룹별 기기 호환 프리셋을 PC에서 실행. Ctrl+Alt+1~9: PC 페이지 1~9 직접 선택. 일반 키 입력 시 확인된 물리 그룹의 0번을 실행합니다.
- 0번을 포함한 페이지 선택은 즉시 전환하며 기기에 쓰지 않습니다. 최초 PC 연결 준비와 명시적인 기기 기록에만 약 4초의 검증 과정이 필요합니다.
- 키 액션의 **PC 페이지 이동**에서 이전·다음·지정 페이지 이동을 설정할 수 있습니다.
- 전환 노브 이외의 키는 **저장 범위 → 모든 PC 페이지 · 공통 기본 키**로 기본 배치를 편집합니다. 페이지별 지정이 우선하며, **별도 설정 지우고 공통 키 사용**으로 다시 상속할 수 있습니다.
- 앱 상단에는 마지막 확인된 기기 그룹·확인 시각과 현재 페이지를 구분해서 표시합니다. 옆면 버튼만 누른 상태는 조회할 수 없으므로, 그룹 변경 후 전환 노브를 한 번 돌려 확인하세요.
- 첫 0번 보관본은 기기의 기존 직접 입력을 보존합니다. 앱 호출 신호만 있던 키는 비워 두며 PC 구성을 자동으로 업로드하지 않습니다. 원하는 액션을 **기기 저장 / 가져오기**에서 복사하거나 0번 전용 편집기에서 저장하세요. 0번은 단축키·미디어·18개 이하 키 조합·비워두기만 허용하며, 고급 PC 매크로는 저장 단계에서도 차단합니다.

기존 설정은 첫 실행 시 `profiles.json.before-v3-*`로 백업합니다. 자세한 동작과 검증 범위는 [PC pages](docs/pc-pages.md)를 참고하세요.

## v2.6 · 업무 프리셋 라이브러리와 OBS

왼쪽 메뉴의 **프리셋 라이브러리**에서 GPT·Claude·Hermes·웨일·Lightroom 5·OBS 추천 6종을 미리 보거나 JSON 파일을 열어 새 PC 페이지로 추가합니다. 기존 페이지·순서·공통 키·실행 설정을 유지하며, 기기에는 기록하지 않습니다. 추가 전 현재 설정을 자동 백업합니다. **선택 페이지 내보내기**는 체크한 페이지들만 파일로 저장합니다. 설정의 **전체 설정 백업 복원**은 기존 구성을 교체하는 별도 기능입니다.

모든 추천 페이지에는 일반 키 15개와 보조 노브 2개의 회전·클릭 동작이 있으며, 그룹 1·2·3에 같은 구성을 배치합니다. 오른쪽 위 노브는 기존 공통 페이지 전환을 유지합니다. GPT는 v2.6.2부터 설치된 ChatGPT Windows 앱의 실제 기능 단축키(새 대화·명령 메뉴·모델·검색·받아쓰기 등)로 구성합니다. Claude·Hermes는 입력창에 요청문을 넣는 구성을 유지합니다. Lightroom은 선별·보정·내보내기와 사진 탐색·선택 슬라이더 조절을 제공합니다.

OBS는 **프리셋 라이브러리 → OBS 연결**에서 서버 연결과 실제 오디오 소스를 확인합니다. 왼쪽 작은 노브는 장면 후보를 보여주고 클릭으로 확정하며, 큰 노브는 지정한 캡처 소스의 볼륨을 한 칸당 1dB 조절하고 클릭으로 음소거합니다. OBS 서버 활성화와 오디오 대상 선택이 필요합니다. 구성 파일과 상세 사용 조건은 [프리셋 안내](presets/README.md)를 참고하세요.

v2.6.1의 **교회 오디오 믹서** 추가 팩은 HDMI·믹서 USB·송출 PC 등 최대 15개 OBS 오디오 소스를 키로 선택하고 큰 노브로 ±0.5dB 조절합니다. 왼쪽 작은 노브는 연결된 소스를 이동하며, 오른쪽 위 노브는 공통 페이지 전환을 유지합니다. 기존 OBS 페이지의 장면 전환·고정 오디오 기능은 그대로 유지합니다. 실제 소스 연결은 해당 PC의 **OBS 연결** 화면에서 설정합니다.

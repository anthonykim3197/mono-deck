# MONO DECK 인수인계서

기준: 2026-11-18 / v2.6.4. 저장소: https://github.com/anthonykim3197/mono-deck

## 프로젝트 목적

A73T 일반 키 15개와 노브 3개(작은 노브 2개, 큰 노브 1개)를 Windows용 컨트롤러로 사용하는 Electron 앱입니다. 한국어 UI, PC 매크로, 기기 매핑 읽기·쓰기, 프리셋과 OBS 제어를 제공합니다. 제조사와 무관한 독립 구현이며 제조사 실행 파일은 포함하지 않습니다.

## 다른 컴퓨터에서 시작

1. 저장소를 clone하고 Codex에서 해당 폴더를 엽니다.
2. 루트 `AGENTS.md`와 이 문서, `README.md`를 읽습니다.
3. Windows x64에서 Node.js 22.12 이상을 준비하고 `npm ci`, `npm run build`, `npm test`를 순서대로 실행합니다.
4. `npm start`로 실행합니다. 배포본은 `npm run package` 후 `release/win-unpacked/` 폴더 전체를 사용합니다.
5. 기기 검증이 필요할 때 해당 PC에 키보드를 연결합니다. 장치가 없어도 소스 수정과 모의 테스트는 가능하지만 모든 네이티브 테스트·실물 동작을 검증할 수 있는 것은 아닙니다.

GitHub에는 코드와 공용 프리셋이 있습니다. 이전 Codex 대화 전체, 개인 설정, 빌드 결과, 로컬 분석 자료는 없습니다. 이전 PC의 설정이 필요하면 양쪽 앱을 종료하고 `%APPDATA%/mono-deck/`를 별도로 백업·이관합니다. 대상 PC에 기존 데이터가 있으면 먼저 보관하세요. OBS 소스, 실행 파일 경로, 모니터 구성을 새 PC에서 확인합니다.

## 현재 기능과 구분

| 개념 | 의미 |
| --- | --- |
| 기기 그룹 1·2·3 | 키보드 옆면 버튼으로 선택하는 물리 그룹. 앱의 그룹 버튼은 편집 대상 선택 |
| 0번 기기 프리셋 | 그룹별로 보관하는 기기 호환 구성. 앱 실행 중에는 PC에서 실행할 수 있음 |
| PC 페이지 1 이후 | 앱이 실행하는 구성. 각 페이지에 그룹 1·2·3의 액션이 존재 |
| 기기에 기록 | 별도 명시적 작업. 페이지 전환과 다르며 백업·쓰기·읽기 검증 수행 |

- Ctrl+Alt+0은 0번, Ctrl+Alt+1~9는 PC 페이지를 즉시 선택합니다. 10번 이후도 오른쪽 위 노브로 접근합니다.
- 공통 전환 노브는 좌/우 회전으로 이전/다음 후보, 클릭으로 확정합니다. 후보는 8초 후 취소됩니다.
- 실제 그룹 표시는 마지막 키/노브 입력에서 확인한 값입니다. 옆면 버튼만 바꿔서는 즉시 확인되지 않습니다.
- PC 매크로는 키보드·마우스 좌표/클릭·지연을 섞고, 반복·조건·녹화를 지원합니다. 최대 500개 동작 노드, 중첩 5단계입니다.
- 테스트한 기기의 온보드 키보드 시퀀스는 최대 18개 modifier/key 쌍입니다. 모든 PC 매크로를 기기에 저장할 수는 없습니다.
- RGB 기본 모드·색상 프리셋을 지원합니다. 임의의 키별 색상·사용자 제작 애니메이션은 지원하지 않습니다.
- 프리셋 라이브러리는 기존 페이지를 보존하며 추가하고, 가져오기/선택 내보내기를 지원합니다.
- OBS 장면 선택과 오디오 제어, 최대 15개 소스 선택용 믹서 프리셋이 있습니다. 소스 연결은 PC별 설정입니다.

## 코드 안내

| 파일 | 담당 |
| --- | --- |
| `src/main/main.cjs` | 앱 수명주기, IPC, 설정 저장, 트레이, 자동 페이지 전환 |
| `src/main/protocol.cjs` | HID 식별·읽기·백업·쓰기·검증 |
| `src/main/onboard.cjs` | 온보드 호환성 및 액션 인코딩/디코딩 |
| `src/main/mode-manager.cjs` | 그룹별 온보드 보관본과 기기 연결 상태 |
| `src/main/macro-engine.cjs` | 혼합 매크로 실행·취소·반복·조건 |
| `src/main/pages.cjs` | 공통 노브, 페이지 이동, 삭제 미리보기·연결 해제 |
| `src/main/presets.cjs`, `obs.cjs` | 프리셋 합치기/내보내기, OBS WebSocket 제어 |
| `native/Bridge.cs` | Windows Raw Input, SendInput, 입력 녹화·좌표·창 조회 |
| `src/renderer/` | React UI와 각 편집 패널 |
| `scripts/build-presets.cjs` | 공용 프리셋 생성. 프리셋 변경 시 생성 원본과 결과를 함께 관리 |
| `tests/` | 프로토콜·설정·매크로·UI 계약·네이티브 회귀 검사 |

설정은 `src/main/config.cjs`에서 검증합니다. 프로필의 `layers['3']`와 기존 호환 필드 `bindings`가 같은 구성을 가리킵니다. 새 IPC는 main, preload, renderer 타입을 함께 수정해야 합니다.

## 데이터와 복구

`%APPDATA%/mono-deck/` 아래 `profiles.json`은 PC 설정, `onboard-banks/`는 그룹별 0번 보관본, `backups/`는 기기 매핑 백업, `page-backups/`는 페이지 삭제 전 전체 설정입니다. `obs-targets.json`은 로컬 OBS 대상 설정입니다. 기기 매핑 백업은 펌웨어 전체·RGB·기존 매크로 타이밍 백업이 아닙니다.

전체 설정 복원은 현재 구성을 교체합니다. 일부 페이지 추가에는 프리셋 라이브러리를 사용합니다. 삭제된 페이지와 기존 연결까지 함께 되돌리려면 삭제 전 전체 설정 백업을 복원합니다.

## 검증 상태와 다음 작업

v2.6.4 기준 Windows x64에서 테스트 152개, TypeScript/Vite/native 빌드, Windows 패키징을 통과했습니다. 실제 기기에서 대표 키의 3개 그룹 구분, 노브 입력, 청록 반응 조명, 매핑 읽기/쓰기 검증을 확인했습니다. 상세 범위는 [verification.md](verification.md)를 따릅니다.

아래는 남은 검증 후보이며 구현 완료로 간주하지 마세요.

- 실제 OBS 서버와 HDMI/USB 믹서 소스를 연결해 장면·음량·음소거 검증.
- 다른 PC·다중 모니터·DPI 조합의 실제 좌표 입력 검증.
- 각 대상 앱의 버전별 프리셋 단축키 검증. 특히 GPT 정의 일치와 실제 실행 검증은 별개입니다.
- RGB 패턴 외형·전원 재연결 후 유지 여부 확인.
- 다른 판매 버전/펌웨어의 호환성 확인. 현재 물리 그룹을 직접 조회하거나 바꾸는 명령은 확인되지 않았습니다.

현재 인수인계 시점에 진행 중인 미완성 코드 수정은 없습니다. 다음 사용자 요청을 기준으로 작업을 선택하세요. 클라우드 작업은 UI·일반 로직·문서·모의 테스트에 활용하고, 최종 Windows 네이티브 및 USB 동작은 장치가 연결된 PC에서 검증하세요.
